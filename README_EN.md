# @hxql/dsh-presentation

[![CI](https://github.com/hxql666/dsh-presentation/actions/workflows/ci.yml/badge.svg)](https://github.com/hxql666/dsh-presentation/actions/workflows/ci.yml)
[![npm](https://img.shields.io/npm/v/@hxql/dsh-presentation?label=npm)](https://www.npmjs.com/package/@hxql/dsh-presentation)
[![license](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

A presentation-document mode for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH):
decks are authored as **structured page data**, compiled to PDF with
[Typst](https://typst.app) + [Touying](https://github.com/touying-typ/touying),
and **rendered back to images so the agent can look at its own output** before
delivering.

## Why this exists

Handing a layout language to a language model produces a deck that is different
every time: type scale, margins, and column ratios drift between runs, page 3 and
page 7 disagree about whitespace, and the model cannot see any of it. Ten
generations give ten visual styles.

This plugin takes the layout away from the model:

- The model emits **structured page data** — a layout id plus slot content. It
  never writes Typst.
- **Sixteen layout primitives** own every typesetting decision.
- After compiling, pages render to PNG and the model reads them back. Overlap,
  clipping, a frame that is nearly empty, a line that does not fit — all visible,
  and fixable, before anyone sees the deck.

### How reproducible, exactly

Measured rather than asserted — `test/determinism-test.mjs`:

| Layer | Result |
|---|---|
| Generated Typst source | byte-identical for the same spec |
| Rendered page PNGs | **pixel-identical** for the same spec |
| The PDF file itself | **not** byte-identical — it carries `/CreationDate` and `/ModDate`. Two builds differ by about 88 bytes and nothing else. |
| After editing one page | with the page **count unchanged**, every other page is pixel-identical |
| After adding or removing a page | **every** page changes — the footer carries a page counter (`2 / 4` → `2 / 5`) |

So the promise is narrow and checkable: **same plugin version, same Typst and
Touying versions, same fonts, same platform, page count unchanged.** Change any of
those and pages may differ. A claim of unconditional reproducibility would be
false, and this table is what replaces it.

### A minimal deck

This deck is written in Chinese on purpose: the two screenshots above are its
own output, so the spec and the pictures have to agree. A deck can be written in
any of the nine locales `deck_status` lists.

```jsonc
{
  "title": "从单体到三个服务",
  "subtitle": "一次拆分复盘",
  "author": "示例作者",
  "locale": "zh",          // zh zh-tw en ja ko de fr es ru
  "theme": "metropolis",   // any of the seven; see deck_status
  "slides": [
    { "layout": "cover" },
    { "layout": "section", "title": "为什么要拆" },
    {
      "layout": "bullets",
      "title": "三个信号",
      "lead": "我们不是在追时髦，是被三件事逼的",
      "items": [
        { "text": "发布互相阻塞", "detail": "一个改动的发布要等另外两个" },
        { "text": "故障域重合", "detail": "一处内存泄漏拖垮整站" },
        { "text": "团队边界模糊", "detail": "没人说得清哪块代码归谁" }
      ],
      "takeaway": "拆分的动机是组织问题，不是技术问题"
    }
  ]
}
```

Pass that to `deck_build`. `deck_status` is the authoritative list of layouts,
themes and scenes; the tables further down are a convenience, not the source of
truth.

These are two different DSH mechanisms, and the distinction matters:

- **Agent preset** — the plugin set an Agent runs on. This is what appears in the
  mode picker alongside standard / PTC / minimal / creative.
- **Collaboration mode** — a toggle inside a session, like `plan`. The plugin's
  `/deck` command is one.

Both arrive from the one package: the preset is declared by the plugin's own
bundle patch, so selecting the card is what mounts the deck tools. There is no
second package to install and no second entry in the plugin list.

**The side effect, stated plainly:** selecting that card mounts this whole plugin,
and while the plugin is in `dsh.profile.bundles` its `/deck` command and five tools
are available whether or not the card is selected. The preset makes "a new session
starts with these tools" a choice; it is not a sandbox.

## Requirements

| | |
|---|---|
| **DSH** | Any version with the plugin and Agent-preset mechanisms this package patches. The bundle patch targets `@deepseek-ai/dsh-agent-preset` and `@deepseek-ai/dsh-app-boot`; a DSH whose entry groups differ will not apply it. Verified against the DSH in this workspace only — no supported-version range is claimed. |
| **Node** | `>=18`, from `engines` in `package.json`. |
| **Operating system** | Windows, Linux and macOS. The Typst compiler ships as six platform-specific optional dependencies (`win32-x64/arm64`, `linux-x64/arm64`, `darwin-x64/arm64`). Development and verification to date has been on **Windows only** — the other five are declared and resolvable but untested by this project. |
| **Typst** | 0.15.1, via the optional dependency, or a system binary you point the plugin at. Touying 0.8.0 requires 0.15.x; a different major will not compile. |
| **Touying** | 0.8.0, vendored inside the package. Nothing is downloaded at build time. |
| **Fonts** | **Not bundled.** The three font stacks name families Typst must already have: New Computer Modern, Libertinus Serif, Noto Sans/Serif SC, Microsoft YaHei, SimSun. All were present on the machine this was developed on; Typst substitutes silently if one is missing, so a deck can render in a different face than the stack asks for. |
| **Profile** | `desktop` throughout this document because that is the profile this was developed against. The plugin is profile-agnostic — substitute your own profile name. |
| **Offline** | Works. The compiler and Touying are both local; nothing is fetched during a build. |

## Install

```bash
dsh plugin --profile desktop add @hxql/dsh-presentation
```

Then **restart the app**. Installed plugins load at startup, and a replaced
package needs a fresh module generation before its new code is used.

After the restart you get two things from that one package:

- a **演示模式** card in **Settings → Agent preset** and in the new-session mode
  picker, and
- the `/deck` command and five deck tools, which mount with that preset.

From a clone, point at the directory instead:

```bash
# Linux / macOS
git clone https://github.com/hxql666/dsh-presentation
cd dsh-presentation
npm install          # fetches the Typst binary for this platform
dsh plugin --profile desktop add "$PWD/packages/dsh-presentation"
```

```powershell
# Windows PowerShell — `$PWD` does not interpolate the same way
git clone https://github.com/hxql666/dsh-presentation; cd dsh-presentation
npm install
dsh plugin --profile desktop add "$((Get-Location).Path)\packages\dsh-presentation"
```

An absolute path works in both: `dsh plugin --profile desktop add /abs/path/to/packages/dsh-presentation`.

### Update, pin and remove

```bash
dsh plugin --profile desktop update @hxql/dsh-presentation
dsh plugin --profile desktop add @hxql/dsh-presentation@0.4.2   # pin a version
dsh plugin --profile desktop remove @hxql/dsh-presentation
```

Restart after each. Removing the plugin leaves your deck directory alone — the
spec, the generated source and the PDFs stay where they are.

### Putting the page images where you want them

`deck_check` writes its PNGs to `preview/` under the deck directory by default.
Pass `outDir` to send them somewhere else — an archive folder, a report's asset
directory:

```jsonc
{ "outDir": "01-talk/pages", "pages": [1, 2, 3] }
```

A relative path resolves against the deck directory, and the directory must stay
inside it. That restriction is deliberate: `outDir` is model-supplied, so it is
untrusted, and **Typst's `--root` confines what a document may read, not where the
compiler writes** — verified by rendering with a pattern outside the compile root,
and the files are written outside it. The containment check in the tool layer is
therefore the only thing standing between a deck spec and an arbitrary write, so it
is a refusal rather than a warning.

The check runs twice, and the second pass is the one that took a measured escape to
find. The first compares path strings; that catches every textual form — `..`,
`..\`, nested traversal, POSIX and drive-letter absolutes, UNC shares, and a
rooted-but-driveless path. It does **not** catch a symlink or junction *inside* the
deck directory: the name passes, and the filesystem sends the write elsewhere.
Measured: writing through such a link succeeded with exit 0 and the file landed
outside the tree, while reading through one is refused. So the second pass resolves
both paths and compares the real ones, walking up to the nearest existing ancestor so
that a directory which does not exist yet still works. All fourteen textual vectors
and the link cases are asserted in `test/escape-vectors-test.mjs`.

### What rendering cleans up

Rendering removes the pages its own previous render wrote, so a directory never
mixes pages from two builds. **What is deleted comes from a manifest**
(`page.manifest.json`, written beside the images), not from a name pattern. The
first implementation matched `page*.png`, which is broader than intent — your own
`page-numbers.png` matches it, and a file this plugin did not write is not its to
remove. A directory that has never been rendered into has no manifest, so nothing in
it is removed at all. Asserted in `test/stale-preview-test.mjs`.

### Why not a git URL

A plugin that ships a platform binary does not install reliably from a git URL,
measured rather than assumed:

| Attempt | Result |
|---|---|
| `dsh plugin add <local clone>/packages/dsh-presentation` | works; the binary resolves |
| a packaged tarball | works; `verified=true`, a deck builds |
| `npm install github:hxql666/dsh-presentation` | **fails** — npm clones the repository and runs its root `prepare` |
| `npm install <repo archive>.tar.gz` | installs, but **`optionalDependencies` are not fetched**, so there is no Typst binary and every build reports `binary-unavailable` |

If a build reports `binary-unavailable`, the platform package did not install.
Fix it either way:

```bash
# inside the installed package directory
npm install

# or point the plugin at a Typst 0.15.1+ binary you already have
#   plugin config:  typstBinaryPath: /absolute/path/to/typst
```

The second option also covers platforms with no bundled binary: 32-bit systems,
`linux-armv7`, and BSD.

## Use

```
/deck                    enter presentation-document mode
/deck handout            handout form (one frame per logical slide)
/deck theme:stargazer    pick a theme
/deck scene:academic     set a standing scene default
/deck scene off          clear it
/deck off                leave
```

Then describe the deck. The intended flow is: `deck_status` for the available
layouts, themes and scenes → plan the page sequence → `deck_build` → `deck_check`
and actually read the rendered images → fix → deliver.

### Tools

Five tools, all available only while the mode is on. Every one of them refuses with
an explanation if the mode is off, and none of them writes anything outside the
deck directory.

| Tool | Parameters | Returns | Notes |
|---|---|---|---|
| `deck_status` | — | mode state, the 16 layouts with their keys, themes, scenes, engine version and whether the Typst binary's hash was verified | Read-only. Call it first; it is the authoritative list rather than this file. |
| `deck_build` | `spec` (required), `scene`, `outFile`, `handout` | `ok`, `pdf`, `specFile`, `pages`, `bytes`, `diagnostics`, `warnings`, `overflow` | Idempotent: the same spec produces the same document. Writes `build/body.typ`, `build/deck.typ`, `build/layout.typ`, `build/deck-spec.json`. Refuses a spec with an empty required slot and compiles nothing in that case. |
| `deck_check` | `pages`, `ppi`, `outDir` | `ok`, `images`, `outDir`, `density`, `tooDense`, `diagnostics` | Writes PNGs for the model to read back. `outDir` must resolve inside the deck directory; a path that escapes is refused, not warned about. Removes only the pages its own previous render recorded in a manifest. |
| `deck_export` | `what` (`vector` \| `handout` \| `notes`), `spec` (for `handout`) | `ok`, `file`, `bytes`, `pages`, `diagnostics` | `vector` and `notes` compile the build that already exists, so they cannot drift from what was reviewed; `handout` rebuilds from its `spec`. |
| `deck_scaffold` | `spec` (required) | `ok`, `specFile`, `typFile` | Writes the generated Typst without compiling. For inspecting the source. |

Error semantics are consistent across all five: a return of `ok: false` always
carries either `message` (what was wrong with the input), `stderr` (what the
compiler said), or `diagnostics`. Nothing fails silently, and no tool throws for a
user-level mistake — a thrown error means the tool was called wrong, not that the
deck was.

### Page layouts (16)

`cover` `section` `agenda` `bullets` `steps` `cards` `kpis` `timeline`
`compare` `quote` `table` `code` `image` `image-text` `columns` `sources`

### Keys for every page type (16)

A misspelled key **does not raise an error** — the page still draws its frame and leaves the content empty. So `deck_build` now checks:
missing required content **refuses the build outright**; a key this page type does not read comes back as a warning and the build still completes.

| layout | keys |
|---|---|
| `cover` | reads the deck-level fields: `title` `subtitle` `author` `institution` `date` |
| `section` | `title` or `kicker` (one is required) |
| `agenda` | `title`, `items[{ text }]` or an array of strings |
| `bullets` | `title`, `lead?`, `items[{ text, detail? }]`, `takeaway?` |
| `steps` | as `bullets`, drawn as a numbered sequence |
| `cards` | `title`, `lead?`, `cards[{ title, eyebrow?, body[], footer? }]`, `perRow?`, `takeaway?` |
| `kpis` | `title`, `lead?`, `items[{ value, label, note? }]`, `takeaway?` |
| `timeline` | `title`, `lead?`, `items[{ when, what? }]`, `takeaway?` |
| `compare` | `title`, `left`, `right` (each `{ title?, items[] }`), `leftTitle?`, `rightTitle?` |
| `quote` | `quote` (required), `author?` |
| `table` | `title`, `lead?`, `headers[]`, `rows[][]`, `takeaway?` |
| `code` | `title`, `lead?`, `source` (required), `language?`, `takeaway?` |
| `image` | `title`, `image` (required), `caption?`, `credit?`, `takeaway?` |
| `image-text` | `title`, `body[]` or `image?`, `caption?` |
| `columns` | `title`, `lead?`, `columns[{ title?, items[] }]`, `ratios?` |
| `sources` | `title`, `lead?`, `items[]` (a numbered reference list), `takeaway?` |

Every page type also accepts `notes`, exported as a pdfpc speaker note.

**Inline emphasis**: `**bold**` and `*italic*` render as real bold and italic; every other special character is escaped, so text written into a deck cannot become Typst syntax. `timeline` still accepts `label`/`detail` as the older spelling.

**An image must live inside the deck directory.** `image` on the `image` and `image-text` pages is a path relative to the deck directory and may not leave it — Typst compiles with that directory as its `--root`, and a path above it is refused with `would escape the project root`. That restriction is also a security boundary: a deck cannot be used to read other files on the machine. Copy the image into the deck directory and reference it by name:

```jsonc
{ "layout": "image", "title": "现场照片", "image": "photo.png",
  "caption": "照片说明", "credit": "来源：某某" }
```

### Scenes

A scene is a starting point for a known kind of talk — theme, frame ratio, font

`tech-talk` · `academic` · `teaching` · `product` · `review` · `pitch`

## Releasing

Publishing happens in CI, not from a laptop.

npm requires an interactive two-factor challenge to publish. The alternatives
are an authenticator app on every release or a granular access token with 2FA
bypass — and npm has announced that those bypass tokens lose direct publish,
targeted January 2027, in favour of trusted publishing.

So `.github/workflows/publish.yml` publishes both packages over OIDC: the
registry verifies that the workflow really ran in this repository. No token is
stored, nothing expires, and no code has to be read out of an app. It runs the
whole suite first, then packs both packages and refuses to publish if a tarball
contains anything it should not.

Run it from **Actions → Publish to npm → Run workflow**, with `dry-run` ticked
to build and verify without publishing.

One-time setup: each package must exist before a trusted publisher can be
registered for it, so a first release has to be done interactively. After that,
register the publisher on npmjs.com for both packages — user `hxql666`,
repository `dsh-presentation`, workflow `publish.yml`.

## Tests

```bash
npm test
```

Runs a type check, then the schema gate, the assembly test, the capability
sweep, the locale and system-Typst checks, the scene tests, the handout check,
and the encoding audit. Install dependencies first (`npm install`) so a platform
Typst binary is present.

The type check is `tsc --checkJs` over the source and its JSDoc. There is no
build step: the plugin ships the JavaScript it runs, so `index.js` stays
readable in the tarball and in a stack trace. What the check buys is that a
contract cannot silently drift from the code — a parameter added to a function
but not to its documentation, or a property read that no longer exists, fails
here rather than at activation.

`types/dsh.d.ts` describes the parts of the host this plugin uses. DSH ships no
type declarations — the installed application contains zero `.d.ts` files — so
that file is written by hand from the plugin's own call sites. It cannot catch
a wrong assumption about the host; the tests are what do that.

The suite covers the failure modes that actually bit this project:

- **A malformed tool schema kills the whole session**, not one tool — the
  provider validates the catalog and rejects every request. `test/schema-gate.mjs`
  compiles and asserts every tool's schemas before installation.
- **A stub that skips validation hides exactly that bug.** `lib/host.js` reproduces
  the host's compile-and-validate pipeline so a definition that would fail at
  activation fails in the test instead.
- **Encoding damage is invisible until it breaks parsing.** A stray BOM or
  mojibake in a manifest is a real defect; the encoding audit sweeps for both.

### Why there is no render cache

A fair question is why `deck_check` re-renders every page instead of only the ones
that changed. Measured — `test/perf-measure.mjs`:

| deck size | build | render all | re-render all | render one page |
|---|---|---|---|---|
| 5 pages | 590 ms | 605 ms | 468 ms | 561 ms |
| 15 pages | 761 ms | 508 ms | 510 ms | 457 ms |
| 40 pages | 763 ms | 802 ms | 734 ms | 779 ms |

**The line that matters is the last two columns: rendering a single page costs about
what rendering all of them costs.** The time is Typst's process start and document
compile; rasterisation is the small part. So a cache that re-renders only what
changed saves very little.

What it would cost is the ability to decide "the source has not changed" correctly —
and getting that wrong is precisely the defect fixed in 0.2.1, where `deck_check`
left old page images in place and reported them as its result, so the model reviewed
**pages that were not in the current deck**. Trading a correctness risk for a few
hundred milliseconds is not a good trade, and the measurement is here so the next
person does not have to repeat the experiment.
